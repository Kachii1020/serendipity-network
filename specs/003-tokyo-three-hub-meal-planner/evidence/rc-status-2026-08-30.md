This ledger records what has been demonstrated in the repository before the
final convergence gate. It is not production evidence.

## Verified implementation facts

- Pack `1.0.0` contains three `ACTIVE` areas: Shibuya, Shinjuku, and
  Ikebukuro. Each contains four activities and three official-menu meals: 21
  places and 40 source records in total.
- The recorded source run passed 9/9 audit regressions, 4/4 typed pack tests,
  and 36/36 live official/license/open-data URLs with HTTP 200–399. Restaurant
  budget constraints use official menus; Tabelog data, reviews, ratings,
  photos, and copied descriptions are absent.
- Contract and engine integration passed the canonical
  `3 areas × party 1/3 × meal on/off` matrix, 12/12. The composer supports
  `Activity → Meal → Activity`, two-stop fallback, activity-only routes,
  per-person/group arithmetic, deterministic IDs, and same-role replacement.
- The v3 runtime exposes search, swap, and evidence APIs with strict v3
  envelopes. The local release harness recorded 20/20 read-only searches with
  unique correlation IDs and p95 19 ms; this is local evidence, not the final
  preview or production reliability result.
- Automated Site Tool tests expose exactly five tools—three read-only and two
  local mutations—and cover validated shared callbacks and registration
  rollback. This does not replace the still-open 3/3 run in a real supported
  Site Tools client.

## Google mode

`GOOGLE_PLACES_ENABLED` remains off because no approved restricted production
key is configured. The server-only adapter and disabled/degraded/known-closed
tests exist; official-menu planning remains functional without Google. No
Google response content is stored in the pack or localStorage. Google-on
policy, attribution, quota, security, and production evidence remain open.

Six of nine meals have an authoritative pre-reviewed Place ID. The three
ICHIRAN records deliberately use `null` because their reviewed official pages
did not expose one; the source audit passes with one enrichment-unavailable
warning per area. This differs from FR-311 and `data-model.md`, which currently
say every meal has a non-null ID. Before T327, either approved IDs must be added
or that contract language must be explicitly reconciled; the mismatch is not a
Google-on pass.
